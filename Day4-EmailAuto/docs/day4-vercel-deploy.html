[01]What got deployed

Vercel imports lw1414/Arca-Academy-Activities-Training, treats the Day4-EmailAuto subfolder as the project root, and serves it as a hybrid project:

  • Static files — the full Tester.io marketing site (index, contact, pricing, dashboard, 11 more pages, all CSS, brand assets)
  • One serverless function — api/briefing.mjs available at /api/briefing
  • Two cron schedules registered from vercel.json — both POST to /api/briefing

The function pulls signups from Supabase, asks Groq to rank them, renders an email-safe HTML template, sends via Resend, and logs the send to your Supabase email_log table.

[04]Manual trigger

From PowerShell:

# Replace with your project subdomain
$URL    = "https://arca-academy-activities-training-pv.vercel.app/api/briefing"
$SECRET = "vuf2j6wUkarqL5KzPh79I8gNmlSGtTJAcZxdnpBoVR0Hsi3b"

# Dry run — renders + summarizes, no email sent
curl.exe "$URL`?dry=1&demo=1&secret=$SECRET"

# Real send with 6 sample leads
curl.exe "$URL`?demo=1&secret=$SECRET"

# Real send with last 24h of live Supabase leads
curl.exe "$URL`?secret=$SECRET"

Expected success response:

{"ok":true,"id":"abc-123-...","provider":"resend","headline":"Strong enterprise interest overnight","total":6}

[05]Cron schedule

Two daily fires registered in vercel.json:

Cron (UTC)Asia/ManilaUse case
30 12 * * *8:30 PMEvening recap
0 23 * * *7:00 AMMorning briefing (per activity spec)

Check Vercel → Settings → Cron Jobs to confirm both rows are registered.

Hobby plan caveat. Vercel rounds cron schedules to daily granularity — fires once per day around that time, not always exactly to the minute. Fine for a morning briefing; not suitable for minute-precise jobs.

[06]Dashboard "Run now"

The dashboard auto-detects where it's hosted:

Opened from"Run now" hits
http://localhost:3000http://localhost:3100/api/briefing/run-now (your watch daemon)
https://...vercel.app/api/briefing?secret=... (same origin)

On Vercel the dashboard will prompt for the BRIEFING_SECRET on first use and cache it in localStorage. To clear it later, open DevTools console and run localStorage.removeItem("brf_secret").

[07]Changing the schedule

01
Open Day4-EmailAuto/vercel.json in the repo.
02
Edit the entries inside crons[]. Schedule strings are UTC cron; convert from Manila by subtracting 8 hours.
03
Commit + push to training/main. Vercel auto-redeploys within ~30s.
04
Refresh Settings → Cron Jobs on Vercel to confirm the new schedule.

Common UTC ↔ Manila conversions

0 7 * * * UTC → 3 PM Manila
0 12 * * * UTC → 8 PM Manila
0 23 * * * UTC → 7 AM Manila
30 12 * * * UTC → 8:30 PM Manila

[10]Cleanup / rollback

To pause the briefing without deleting:

  • Vercel → Settings → Cron Jobs → toggle each cron OFF
  • Or remove the crons array from vercel.json and push → redeploy

To delete the deployed project:

  • Vercel → Settings → Advanced → Delete Project
  • Repo files stay intact; you can re-deploy any time

To revert any code change:

git revert <commit-sha>
git push training

Vercel auto-redeploys from the revert commit.
